# QA 리포트 — 룰북 v4.1 대비 구현 점검 및 수정 (2026-10)

점검 방법

1. 룰북(`rulebook/game_rule_v4.1.md`, `game_card_v4.1.md`)과 백엔드 서비스 코드를 줄 단위로 대조
2. 로컬 PostgreSQL에 스키마·카드를 올리고 **수정 전 코드로 실제 게임을 끝까지 실행** → 문제 재현
3. 수정 후 `scripts/simulate-game.mjs`로 2·3·4·5인 게임을 반복 실행하고, Playwright로 실제 UI 흐름(로비 → 14일 → 결산 → 결과, 새로고침 포함) 확인

## 수정 전 재현 결과 (3인, 사람 1 + AI 2)

| 플레이어 | 구매 카드 | 최종 점수 |
| --- | --- | --- |
| AI 1 | (구매 안 함) | 7 |
| AI 2 | (구매 안 함) | 6 |
| 사람 | 5장 구매 | 6 |

→ 구매한 카드가 점수에 반영되지 않고, 세 명의 특성치가 모두 같았음.

## 발견한 문제와 수정

### 치명적 (게임 결과가 틀리거나 진행 불가)

| # | 문제 | 원인 | 수정 |
| --- | --- | --- | --- |
| 1 | 구매한 계획 카드가 점수에 반영되지 않음 | 최종 구매가 `purchased`에 기록만 하고 특성치에 더하지 않음 | 구매 시 효과를 특성에 누적 (`GameFinalizationService`) |
| 2 | 여행지 가중치(×3/×2)가 적용되지 않음 | 존재하지 않는 `player_states.travel_card_id` 컬럼을 참조해 항상 ×1 | 획득한 여행지 카드에서 가중치 조회 (`rules.multipliersFromTravelCard`) |
| 3 | 첫 사람이 구매하자마자 결과 확정 | "구매 완료" 판정이 `purchased` 존재 여부인데 여행지 카드가 이미 들어 있음 | 플레이어별 `final_submitted` 기록으로 전원 제출 확인 |
| 4 | AI가 최종 구매를 안 함 | AI를 닉네임 `LIKE '%봇%'`으로 찾는데 "컴퓨터/알고리즘" 이름은 누락 | `players.is_ai` 사용 |
| 5 | 3인 이상에서 사람이 뽑은 찬스 카드 효과 없음 | 행동 5번이 카드만 뽑고 효과를 실행하지 않음 | 드로우 직후 `ChanceService.executeCard` 실행 |
| 6 | AI가 뽑은 찬스 카드·무료 계획 효과 없음 | AI가 별도 코드로 덱을 직접 조작 | AI도 `TurnService`를 통해서만 행동 |
| 7 | 찬스 상호작용 선택창이 안 뜸 (30초 후 실패) | 소켓 이벤트를 아무도 참여하지 않은 `gameId` 방으로 전송 | `roomId`로 전송, 요청자에게만 표시, 60초 후 자동 선택 |
| 8 | CH9/14/15/22 사용 시 서버 오류 | JSONB 배열에 `JSON.parse` 호출 | 공용 `DeckService.drawCard` 사용 |
| 9 | 덱이 바닥나면 행동이 실패해 게임 정지 | 재충전 규칙 미구현 (집안일 13장 등) | 룰북 10장대로 버린 카드 재셔플, 완전 소진 시 "카드 없음" 처리 |
| 10 | 서버 재시작 후 진행 중 게임 조작 불가 | 턴 락이 메모리에만 있고 복원 비활성화 | 시작 시 DB에서 턴 락 복원, 멈춘 AI 턴 재개 |
| 11 | 아무나 남의 턴을 종료 / 행동 없이 종료 가능 | `end-turn`에 검증 없음 | 현재 턴 플레이어 + 주 행동 완료 시에만 종료 |
| 12 | 임의의 찬스 카드를 언제든 실행 가능 | `POST /games/:id/chance/:cardCode` 공개 | 엔드포인트 제거 |

### 해석이 필요했던 부분 (구현 기준)

- **CH20 공동 목표 지원**: "기여 +3,000TC"를 무료 지원으로 해석 (본인 TC 차감 없음, 본인 기여액으로 집계)
- **CH25 동행 버디**: 본인은 즉시 추가 행동 1회, 지목된 플레이어는 결심 토큰 +1 (다음 자기 턴에 행동 1회)
- **CH13 자리 바꾸기**: 이미 행동한 요청자는 추가 행동 없음 (룰북 6.2)
- **F5 친구랑 놀기**: 지정 친구는 다음 차례 플레이어
- **캐치업 카드(가장 적은 사람)**: 동률이면 해당 플레이어 전원

## 남은 과제

- 플레이어 인증 없음 (요청 본문의 `playerId`를 신뢰) — 공개 서비스로 운영하려면 세션 토큰 필요
- 상대 손패가 `/state` 응답에 포함됨 (화면에는 장수만 표시)
- 턴 락이 단일 서버 메모리 기준 — 서버를 여러 대로 늘리면 Redis 등 공유 저장소 필요
